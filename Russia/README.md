# BlockAds RU для Shadowrocket

Адаптация [fmz200/wool_scripts](https://github.com/fmz200/wool_scripts) для российских и международных сайтов. **Один модуль содержит доменные правила и MITM-обработчики YouTube, Reddit и TikTok Web. X работает без MITM и без блокировки его служебных доменов.** Эта версия расположена только в папке `Russia/`. Остальные папки форка содержат исходный проект; их не нужно подключать вместе с этой версией.

Версия **2026.09.14.3** уменьшает лишнюю обработку Reddit, ограничивает фрагментацию бинарных ответов и учитывает дополнительные исключения совместимости AdGuard. Пользователь подтвердил работу X на iPhone после исправления в версии 2026.09.14.2; исключение X из перехвата и блокировки сохранено. Полного удаления рекламы во всех приложениях эта версия не обещает.

## Подключение

В Shadowrocket откройте «Конфиг / Config» → «Модули / Modules» → `+` и добавьте **единственную ссылку**:

[**Скачать blockAds-RU.module**](https://raw.githubusercontent.com/pivazyaa/blockads-ru/main/Russia/blockAds-RU.module)

Если эта ссылка уже добавлена, **обновите существующий модуль**. В описании должна появиться версия `2026.09.14.3`. Внутри находятся 2 026 доменных правил, четыре обработчика и список из 11 MITM-хостов. JavaScript-файлы Shadowrocket загружает автоматически; отдельно импортировать их не нужно. Общая маршрутизация должна использовать конфигурацию (`Config`). Основную подписку VPN обновлять для этого не требуется.

Отключите старый общий fmz200 blockAds и отдельно добавленные `YouTube-RU`, `Reddit-RU`, `X-RU`, `TikTok-Web-RU`, если они уже установлены. Поддерживаемые обработчики уже встроены в единый модуль. Старый `X-RU` при обновлении становится пустым совместимым модулем, чтобы не возвращать проблемный перехват. Отдельные файлы сохранены для обновления старых установок; добавлять их не нужно.

Доменные правила работают без сертификата. Для встроенной MITM-части один раз создайте **собственный сертификат на каждом iPhone**: настройки используемого конфига → HTTPS Decryption → Certificates → Generate New CA → Install. Затем установите профиль в настройках iOS и включите доверие этому сертификату в «Основные» → «Об этом устройстве» → «Доверие сертификатам». Включите HTTPS Decryption для используемого конфига. Если свой сертификат уже установлен и доверен, повторно создавать его не требуется. Названия пунктов могут отличаться по языку и версии приложения. См. [инструкцию разработчика Shadowrocket](https://github.com/Shadowrocket/manual/issues/2).

В репозитории нет готового CA, его пароля или приватного ключа. Сертификат с другого устройства скачивать не нужно. Расшифровка происходит на телефоне для перечисленных в модуле хостов; это не означает передачу открытого трафика на VPS. Если приложение использует certificate pinning, оно может отвергнуть такой сертификат ещё до запуска скрипта. Тогда его хост нужно исключить из HTTPS-расшифровки.

## Что изменено

- Единый модуль около **80 КБ** вместо 435 КБ исходного Shadowrocket-модуля. Сотни обработчиков китайских приложений и широкие правила по ключевым словам исключены.
- Добавлены доменные правила AdGuard Base, Mobile и Russian/Cyrillic. В генератор попадают только безусловные правила целого домена. Ограничения `$third-party`, `$domain=`, `$app=`, пути и wildcard-правила не превращаются в глобальный запрет. Правила с известными исключениями пропущены; причины сохранены в `sources.lock.json`.
- Учтены доменные wildcard-исключения с фиксированной доменной частью: глобальная блокировка больше не перекрывает `api*-access-sg.pangle.io` и `i*-tb.isnssdk.com`. Upstream использует их для совместимости отдельных Android-приложений; это не утверждение о воспроизведённом сбое на iPhone. Остальные рекламные адреса семейства `isnssdk.com` не отключаются целиком.
- Удаление дублей и поддоменов, уже покрытых родительским правилом. Нет загрузки дополнительных списков во время работы.
- X, Twitter, t.co и twimg не расшифровываются. Удалена блокировка `ads-bidder-api.twitter.com`; остальные служебные домены X также защищены от добавления в блокировку при пересборке. Это не правило DIRECT: маршрут X по-прежнему выбирает основной VPN-конфиг.
- Нет изменений DNS, прокси, маршрута российских сайтов, T-Банка и Apple. Рекламные домены блокируются до выбора DIRECT/PROXY; остальной трафик обрабатывает ваш основной конфиг.
- Убраны блокировки Safe Browsing и вмешательство в возрастные настройки Reddit. Apple ID, iCloud, платежи, push, проверка сертификатов и обновления ОС не перехватываются этими модулями.
- Скрипты ограничены телом 1 МиБ для JSON и 2 МиБ для YouTube protobuf; timeout 5 секунд, движок `jsc`. Внутри есть пределы обхода и времени. Неизвестный, повреждённый или неподдерживаемый ответ возвращается без изменений. При отсутствии рекламы текст ответа не пересобирается.
- JSON без рекламных признаков пропускается до разбора. Лимит работы теперь учитывает плоские массивы, отдельные значения и вложенные рекламные ячейки. Частичные GraphQL-ошибки и NDJSON сохраняются без изменений. Массивы очищаются внутри разобранной копии без создания второго массива такого же размера.
- Обычные HTML-страницы Reddit не запускают обработчик тела ответа. OAuth-ленты с URL вида `/hot?limit=25`, без завершающего `/`, теперь распознаются; явные веб-адреса `.json` остаются поддержаны. Пути сверены с [API Reddit](https://www.reddit.com/dev/api/#GET_hot). Список MITM-хостов не расширен.
- Нет сетевых запросов из скриптов, записи cookies, постоянного хранилища, уведомлений или журналирования содержимого. Скрипты закреплены на конкретном Git-коммите; изменение чужого `master` не меняет их код.
- YouTube-скрипт удаляет только поля `adPlacements` и `adSlots` в protobuf Player и документированном вложении `get_watch`; остальные байты сохраняет. Поддерживает бинарные `body`/`bodyBytes` и смещение typed-array/DataView. Размер и тип проверяются до преобразования; для неизменённых полей не создаётся отдельная временная копия/представление. Не изменяет `googlevideo.com`, `initplayback`, настройки воспроизведения, субтитры, Premium или фоновые функции.
- Дополнительно проверяется сам MIME-тип, а не слово `protobuf` в произвольном параметре заголовка. Число выходных фрагментов ограничено 4 096 на весь ответ, включая вложенные Player-сообщения. При превышении лимита исходный ответ проходит без изменений.

## Реальные ограничения по приложениям

| Где | Что можно ожидать и что ещё не проверено |
|---|---|
| Российские сайты и приложения | Блокировка отдельных рекламных доменов. Реклама с общего API или прямо в HTML может остаться. Известные исключения для совместимости имеют приоритет над количеством блокировок. |
| YouTube | Поддерживаемые player/get_watch и веб-JSON могут очищаться от рекламных полей. Варианты SSAI, новые protobuf-поля, A/B-форматы и реклама в нативной ленте не покрыты полностью. Обычные видео и интеграции автора не вырезаются. |
| Reddit | Обрабатываются известные признаки AdPost, AdMetadataCell, adPayload и promoted. NSFW остаётся как в исходном ответе. Неизвестная схема пропускается. |
| X | MITM и обработка ответов отключены после подтверждённого конфликта с iPhone. Реклама внутри ленты X может оставаться. Вход, сообщения, посты, изображения и видео не изменяются этим модулем. |
| TikTok | Встроенный обработчик предназначен только для веб-ленты. MITM нативного iOS-приложения и его актуальная схема не подтверждены. Нельзя выдавать старые Douyin-правила за проверенную поддержку TikTok. |
| Telegram | Встроенная реклама приходит через Telegram API/MTProto. HTTPS-модуль Shadowrocket не умеет вырезать эти сообщения; отдельного работающего Telegram MITM-модуля здесь нет. См. [API sponsored messages](https://core.telegram.org/api/sponsored-messages). |
| Widgetable | База блокирует часть распространённых рекламных SDK. Актуальные запросы Widgetable не записывались, поэтому удаление всей рекламы не подтверждено. Действия за просмотр rewarded-рекламы могут стать недоступны; награды и покупки не подделываются. |
| Apple | Блокируется часть отдельных рекламных адресов. Рекламные вставки и собственные предложения в App Store, News, TV и других сервисах могут остаться. Общий MITM `*.apple.com`/`*.icloud.com` не используется: [Apple предупреждает о несовместимости своих служб с HTTPS-перехватом](https://support.apple.com/en-us/101555). |
| Happ | Этот MITM-модуль предназначен для Shadowrocket. Поддержка такого формата скриптов в Happ не заявляется. |

Для сайтов в Safari полезно дополнительно включить **Safari-защиту AdGuard** с базовым, мобильным и русским фильтрами: она видит элементы страницы и контекст запросов, которых нет у доменного VPN-блокировщика. [Описание Safari-защиты](https://adguard.com/kb/adguard-for-ios/features/safari-protection/). Чтобы сохранить текущую VPN-схему, для этого достаточно Safari-защиты, без включения второго локального VPN/DNS-профиля AdGuard.

## Проверка на iPhone

После обновления модуля проверьте вход в приложения, обновление лент, комментарии, поиск, воспроизведение нескольких видео и загрузку следующей страницы. Отдельно проверьте App Store, iCloud, уведомления, оплату/банковское приложение и синхронизацию Widgetable.

Для X обновите модуль, включите его, полностью закройте и снова откройте приложение X. Если старые X/Twitter-хосты были вручную скопированы в HTTPS Decryption основного конфига, удалите только их оттуда. Не отключайте проверку сертификатов и не переустанавливайте CA для исправления X.

Если приложение перестало открываться после установки, временно выключите `BlockAds RU` в Modules и снова проверьте приложение. Затем можно исключить только его хост из MITM или отключить соответствующий обработчик внутри модуля. Скрипт умеет пропускать неподдерживаемое содержимое, но не может исправить TLS-ошибку или certificate pinning до получения ответа. Сервер для этого перезапускать не нужно.

Если реклама осталась, для точной правки достаточно версии приложения, имени хоста, пути без параметров и типа ответа. Cookies, Authorization, полный URL с токеном, содержимое личных сообщений и банковские ответы публиковать не нужно.

## Проверки и воспроизводимость

`test-results.json`: **52 проверки** в V8 на синтетических данных, все прошли. В том числе сохранение NSFW, обычного контента, курсоров, 64-битных protobuf-значений, неизвестных полей; обход X, частичных GraphQL-ошибок и NDJSON; ограничение больших плоских массивов, двоичные буферы с ненулевым смещением, проверка MIME, путей Reddit и общей фрагментации вложенных ответов. Пять новых проверок не проходили на версии 2026.09.14.2. Результат тестов не равен проверке реальных приложений.

Специальный нагрузочный пример: protobuf 200 КБ с чередующимися обычными и рекламными полями раньше создавал 50 000 временных представлений буфера. Новая версия останавливает преобразование после 4 096 и отдаёт исходный ответ. Это ограничение расхода памяти на необычных данных; сетевой пинг и скорость iPhone этим тестом не измеряются. Профиль сохранён в `test-results.json`.

`validate-release.ps1` проверяет структуру модулей, закрепление ссылок, совпадение URL-правил, отсутствие перехвата банковских адресов и сохранение критических доменов. Дополнительно проверяются четыре поддерживаемых обработчика, покрытие MITM-хостов, отсутствие дублей и защита X во всех публикуемых модулях. Для повторения тестов:

```powershell
node test-blockads.js
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\test-source-exceptions.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\validate-release.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-rules.ps1
```

Первый тест требует Node.js. Генератор читает локальный `mitm-config.json`, при необходимости скачивает доменные списки по закреплённым коммитам, не исполняет скачанный код, создаёт единый модуль и совместимые старые модули в `publish/`. Старые скачанные MITM-модули больше не используются как источник, поэтому пересборка не возвращает перехват X. Генератор ничего не публикует автоматически. `ExecutionPolicy Bypass` действует только на запущенный процесс и не меняет системную настройку PowerShell.

Reddit-признаки взяты из работы fmz200/xream; номера YouTube protobuf-полей сверены с [Maasea/sgmodule](https://github.com/Maasea/sgmodule/blob/65075cdb388fc5e3094afd7e7314c67b243f3525/Script/Youtube/youtube.response.js). Новый минимальный protobuf-парсер написан отдельно; полный скрипт Maasea не загружается. Полные сведения о доменных источниках, исключениях и SHA-256 файлов: `sources.lock.json`.

# BlockAds RU для Shadowrocket

Адаптация [fmz200/wool_scripts](https://github.com/fmz200/wool_scripts) для российских и международных сайтов. **Один модуль содержит доменные правила и MITM-обработчики YouTube, Reddit, X и TikTok Web.** Эта версия расположена только в папке `Russia/`. Остальные папки форка содержат исходный проект; их не нужно подключать вместе с этой версией.

Единая версия от 14 сентября 2026 года. Проверены код и синтетические примеры ответов; работа в установленной версии Shadowrocket и в аккаунтах на iPhone пока не подтверждена. Полного удаления рекламы во всех приложениях и отсутствия любых сбоев эта версия не обещает.

## Подключение

В Shadowrocket откройте «Конфиг / Config» → «Модули / Modules» → `+` и добавьте **единственную ссылку**:

[**Скачать blockAds-RU.module**](https://raw.githubusercontent.com/pivazyaa/blockads-ru/main/Russia/blockAds-RU.module)

Если эта ссылка уже добавлена, **обновите существующий модуль**. Внутри уже находятся 2 029 доменных правил, пять обработчиков и список из 15 MITM-хостов. JavaScript-файлы Shadowrocket загружает автоматически; отдельно импортировать их не нужно. Общая маршрутизация должна использовать конфигурацию (`Config`). Основную подписку VPN обновлять для этого не требуется.

Отключите старый общий fmz200 blockAds и отдельно добавленные `YouTube-RU`, `Reddit-RU`, `X-RU`, `TikTok-Web-RU`, если они уже установлены. Их обработчики теперь встроены в единый модуль; одновременная обработка одного ответа может вызвать ошибки. Отдельные файлы сохранены в репозитории для старой версии, но для новой установки не нужны.

Доменные правила работают без сертификата. Для встроенной MITM-части один раз создайте **собственный сертификат на каждом iPhone**: настройки используемого конфига → HTTPS Decryption → Certificates → Generate New CA → Install. Затем установите профиль в настройках iOS и включите доверие этому сертификату в «Основные» → «Об этом устройстве» → «Доверие сертификатам». Включите HTTPS Decryption для используемого конфига. Если свой сертификат уже установлен и доверен, повторно создавать его не требуется. Названия пунктов могут отличаться по языку и версии приложения. См. [инструкцию разработчика Shadowrocket](https://github.com/Shadowrocket/manual/issues/2).

В репозитории нет готового CA, его пароля или приватного ключа. Сертификат с другого устройства скачивать не нужно. Расшифровка происходит на телефоне для перечисленных в модуле хостов; это не означает передачу открытого трафика на VPS. Если приложение использует certificate pinning, оно может отвергнуть такой сертификат ещё до запуска скрипта. Тогда его хост нужно исключить из HTTPS-расшифровки.

## Что изменено

- Единый модуль около **80 КБ** вместо 435 КБ исходного Shadowrocket-модуля. Сотни обработчиков китайских приложений и широкие правила по ключевым словам исключены.
- Добавлены доменные правила AdGuard Base, Mobile и Russian/Cyrillic. В генератор попадают только безусловные правила целого домена. Ограничения `$third-party`, `$domain=`, `$app=`, пути и wildcard-правила не превращаются в глобальный запрет. Правила с известными исключениями пропущены; причины сохранены в `sources.lock.json`.
- Удаление дублей и поддоменов, уже покрытых родительским правилом. Нет загрузки дополнительных списков во время работы.
- Нет изменений DNS, прокси, маршрута российских сайтов, T-Банка и Apple. Рекламные домены блокируются до выбора DIRECT/PROXY; остальной трафик обрабатывает ваш основной конфиг.
- Убраны блокировки Safe Browsing и вмешательство в возрастные настройки Reddit. Apple ID, iCloud, платежи, push, проверка сертификатов и обновления ОС не перехватываются этими модулями.
- Скрипты ограничены телом 1 МиБ для JSON и 2 МиБ для YouTube protobuf; timeout 5 секунд, движок `jsc`. Внутри есть пределы обхода и времени. Неизвестный, повреждённый или неподдерживаемый ответ возвращается без изменений. При отсутствии рекламы текст ответа не пересобирается.
- Нет сетевых запросов из скриптов, записи cookies, постоянного хранилища, уведомлений или журналирования содержимого. Скрипты закреплены на конкретном Git-коммите; изменение чужого `master` не меняет их код.
- YouTube-скрипт весит около 4,4 КБ. Удаляет только поля `adPlacements` и `adSlots` в protobuf Player и документированном вложении `get_watch`; остальные байты сохраняет. Не изменяет `googlevideo.com`, `initplayback`, настройки воспроизведения, субтитры, Premium или фоновые функции.

## Реальные ограничения по приложениям

| Где | Что можно ожидать и что ещё не проверено |
|---|---|
| Российские сайты и приложения | Блокировка отдельных рекламных доменов. Реклама с общего API или прямо в HTML может остаться. Известные исключения для совместимости имеют приоритет над количеством блокировок. |
| YouTube | Поддерживаемые player/get_watch и веб-JSON могут очищаться от рекламных полей. Варианты SSAI, новые protobuf-поля, A/B-форматы и реклама в нативной ленте не покрыты полностью. Обычные видео и интеграции автора не вырезаются. |
| Reddit | Обрабатываются известные признаки AdPost, AdMetadataCell, adPayload и promoted. NSFW остаётся как в исходном ответе. Неизвестная схема пропускается. |
| X | Удаляются записи с promoted-entry и promotedMetadata. Платная публикация без этих признаков может остаться. Вход, сообщения и платежные операции не входят в URL-правила скрипта. |
| TikTok | Дополнение предназначено только для веб-ленты. MITM нативного iOS-приложения и его актуальная схема не подтверждены. Нельзя выдавать старые Douyin-правила за проверенную поддержку TikTok. |
| Telegram | Встроенная реклама приходит через Telegram API/MTProto. HTTPS-модуль Shadowrocket не умеет вырезать эти сообщения; отдельного работающего Telegram MITM-модуля здесь нет. См. [API sponsored messages](https://core.telegram.org/api/sponsored-messages). |
| Widgetable | База блокирует часть распространённых рекламных SDK. Актуальные запросы Widgetable не записывались, поэтому удаление всей рекламы не подтверждено. Действия за просмотр rewarded-рекламы могут стать недоступны; награды и покупки не подделываются. |
| Apple | Блокируется часть отдельных рекламных адресов. Рекламные вставки и собственные предложения в App Store, News, TV и других сервисах могут остаться. Общий MITM `*.apple.com`/`*.icloud.com` не используется: [Apple предупреждает о несовместимости своих служб с HTTPS-перехватом](https://support.apple.com/en-us/101555). |
| Happ | Эти MITM-дополнения предназначены для Shadowrocket. Поддержка такого формата скриптов в Happ не заявляется. |

Для сайтов в Safari полезно дополнительно включить **Safari-защиту AdGuard** с базовым, мобильным и русским фильтрами: она видит элементы страницы и контекст запросов, которых нет у доменного VPN-блокировщика. [Описание Safari-защиты](https://adguard.com/kb/adguard-for-ios/features/safari-protection/). Чтобы сохранить текущую VPN-схему, для этого достаточно Safari-защиты, без включения второго локального VPN/DNS-профиля AdGuard.

## Проверка на iPhone

После обновления модуля проверьте вход в приложения, обновление лент, комментарии, поиск, воспроизведение нескольких видео и загрузку следующей страницы. Отдельно проверьте App Store, iCloud, уведомления, оплату/банковское приложение и синхронизацию Widgetable.

Если приложение перестало открываться после установки, временно выключите `BlockAds RU` в Modules и снова проверьте приложение. Затем можно исключить только его хост из MITM или отключить соответствующий обработчик внутри модуля. Скрипт умеет пропускать неподдерживаемое содержимое, но не может исправить TLS-ошибку или certificate pinning до получения ответа. Сервер для этого перезапускать не нужно.

Если реклама осталась, для точной правки достаточно версии приложения, имени хоста, пути без параметров и типа ответа. Cookies, Authorization, полный URL с токеном, содержимое личных сообщений и банковские ответы публиковать не нужно.

## Проверки и воспроизводимость

`test-results.json`: **32 проверки** в V8 на синтетических данных, все прошли. В том числе сохранение NSFW, обычного контента, курсоров, 64-битных protobuf-значений, неизвестных полей; отказ от обработки HTML, ошибок, усечённых protobuf и чрезмерных тел. Результат тестов не равен проверке реальных приложений.

Один замер: 100 JSON-лент по 100 записей обработаны за 28 мс в тестовом V8-окружении. Это не замер задержки сети, автономности или скорости iPhone. Результат на JSC в Shadowrocket ещё не измерен.

`validate-release.ps1` проверяет структуру модулей, закрепление ссылок, совпадение URL-правил, отсутствие перехвата банковских адресов и сохранение критических доменов. Для единого модуля дополнительно проверяется наличие всех пяти обработчиков, покрытие MITM-хостов и отсутствие дублирующихся секций. Для повторения тестов:

```powershell
node test-blockads.js
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\validate-release.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build-rules.ps1
```

Первый тест требует Node.js. Генератор при необходимости скачивает списки и описания встроенных обработчиков по закреплённым коммитам, не исполняет скачанный код, создаёт единый модуль в `publish/` и ничего не публикует автоматически. `ExecutionPolicy Bypass` действует только на запущенный процесс и не меняет системную настройку PowerShell.

Исходники и лицензия GPL-3.0 находятся в этой папке. Базовый fmz200-коммит: `3ca7487b4e4b86d9af76e50df72c62eacfbb659e`. AdGuard-коммит: `ebd6f4bc46f816cf75a41c9764dd35bed4a65b00`. Reddit-признаки взяты из работы fmz200/xream; номера YouTube protobuf-полей сверены с [Maasea/sgmodule](https://github.com/Maasea/sgmodule/blob/65075cdb388fc5e3094afd7e7314c67b243f3525/Script/Youtube/youtube.response.js). Новый минимальный protobuf-парсер написан отдельно; полный скрипт Maasea не загружается. Полные сведения о доменных источниках, исключениях и SHA-256 файлов: `sources.lock.json`.
